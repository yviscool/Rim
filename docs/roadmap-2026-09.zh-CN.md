# Rim 下一轮架构与工作规划

本文基于当前工作树、核心代码、已有架构/手势调研文档，以及本地 AutoHotkey v2 探针结果整理。它描述下一轮工作的排序和验收方式，不把当前未提交改动视为已经完成的版本。

## 当前系统理解

Rim 已经形成一条完整的 Windows 输入工作流：启动阶段加载配置和文件命令，RimCommand 维护语义命令，SearchCommand 负责搜索和展示，ExecuteAction 负责统一执行；VimEngine 负责窗口识别、模式、计数和按键分发；GestureHook、GestureRecognizer、GestureEngine 负责鼠标钩子、轨迹识别、候选选择和动作执行；RimContext 向命令提供活动窗口上下文；RimPluginManager 通过生命周期阶段把插件接入这些核心服务；配置 GUI 已开始使用 ConfigSchema、校验、订阅、预览和保存事务。

当前架构的主要矛盾是：模块边界已经出现，但运行时仍由全局状态和 #Include 的单一命名空间连接。因此新功能可以较快加入，但长期维护、重载、冲突诊断和性能测量仍缺少统一基础设施。

## 证据和现状

- 仓库约有 113 个 .ahk 文件；核心约 10,735 行，插件约 13,501 行，GUI 约 3,517 行。
- 已通过的本地探针覆盖解析、注册、命令、上下文、插件、工作区、手势、配置 schema、Vim 热键、无钩子/全局钩子和手势 UI 几何。
- 当前手势 benchmark 为 99 个样本、100% 命中，最近一次 P95 为 31ms；样本主要来自同源模板和构造轨迹，不能代表真实用户准确率。
- CI 任务名称写的是 P95<=30ms，benchmark 脚本实际按 <=50ms 退出；CI 目前只检查报告文件存在，没有解析报告中的数值。
- benchmark_out.txt 为空，而脚本实际写入 tools/benchmark_report.txt，性能产物路径还未统一。
- 生产代码仍有大量直接访问 g_Conf，CfgGet 已存在但尚未成为统一入口；手势配置写入也直接操作 g_Conf 和 INI 文件。
- 工作树已有一组未提交改动，涉及配置 schema/UI、手势状态、Vim 分发、插件拆分、语言文件和探针。下一轮应先分类和建立提交边界，避免把不同风险级别的变更混成一个版本。

## 四个维度的评估

| 维度 | 当前成熟度 | 主要风险 | 判断依据 |
|---|---|---|---|
| 维护性 | 中等偏低 | 全局状态、#Include 顺序、动作字符串兼容层、配置直接访问，导致隐式依赖和回归难定位 | g_Conf 在核心、插件、GUI 中广泛出现；ExecuteAction 与 RimCommand.Execute 仍保留兼容/递归路径 |
| 拓展性 | 中等 | 插件生命周期已经统一，但缺少能力声明、依赖、版本、命令冲突和失败报告；手势定义仍有硬编码分支 | RimPluginManager 已有六阶段，但 Register 只保存类，注册结果和冲突没有结构化返回 |
| 性能 | 中等，热点明确 | 搜索全量扫描和重复字符串构造；窗口匹配、上下文捕获和插件/命令池可能重复工作；日志无轮转 | SearchCommand 每次输入遍历命令；CheckWin 主要靠线性匹配；上下文捕获会读取多项 Win32 属性 |
| 功能可靠性 | 核心路径较好，真实桌面覆盖不足 | 鼠标短点/拖拽回放、菜单焦点、多屏/DPI、权限/UIPI、睡眠唤醒仍需真机验证；手势 benchmark 缺少独立测试集 | headless 探针通过，但 Explorer、TC、浏览器和多 DPI 场景尚未形成自动化回归 |

## 下一轮工作排序

### P0：先建立可发布基线

1. **整理工作树和提交边界**：把现有改动按配置 schema/UI、手势、Vim 分发、插件拆分、CI/探针分组，逐组运行最小探针；删除或忽略日志和 benchmark 临时产物。验收：每组改动可独立审阅，git diff --check 清零，入口和 #Include 顺序有可验证清单。

2. **修正 CI 性能门禁**：统一报告路径；输出机器可解析的 metric=value；用多轮统计报告 warm-up、P50/P95/P99、最大值；建议 P95 目标 30ms，30--50ms 告警，超过 50ms 失败。验收：故意缩小阈值能让 CI 失败，报告不再依赖空的 benchmark_out.txt，连续运行波动可解释。

3. **输入安全回归矩阵**：覆盖短点未命中、右键拖动、窗口外松手、长按、滚轮、多屏、125%/150% DPI、菜单打开、提权窗口。headless 验证状态机和回放序列，桌面测试验证消息、焦点和前台窗口。验收：未命中手势不吞完整鼠标序列，异常/隐藏/退出时捕获状态均清理，菜单交互不依赖 Send 竞态。

### P1：收口配置、执行和插件边界

4. **配置服务化迁移**：以 CfgGet/CfgValidate/CfgSubscribe 为唯一读取和变更入口，先迁移 Core/Execution、Search、GUI、Files，再迁移插件和手势；增加 oldValue/newValue/scope/source 事件；保存采用校验、临时文件、替换、重新加载、发布的事务流程。验收：缺键回 schema 默认，非法值不落盘，live/rebuild/restart scope 可由探针验证，取消不产生半保存。

5. **统一动作协议**：定义结构化动作对象，让文件命令、插件命令、手势和历史记录经过同一解析器；字符串协议只留边界兼容层，增加循环检测、错误码和来源日志，逐步移除双向兜底。验收：Launcher、Vim、手势、历史执行一致，自指和未知动作有确定错误，日志包含来源插件和命令 ID。

6. **插件契约第二版**：增加 Id/Version/ApiVersion/Dependencies/Capabilities；注册返回结构化结果；管理器增加依赖排序、命令/快捷键/手势冲突检测、阶段失败报告和禁用原因。验收：禁用或缺依赖插件不阻塞主程序，冲突显示双方 ID 和注册点，异常包含阶段、版本和堆栈。

7. **日志和诊断基础设施**：统一日志等级、分类、会话 ID和轮转；生产默认 INFO，调试才打开详细输入/匹配日志；避免记录剪贴板和输入正文。验收：一次命令或手势可串起捕获、识别、选择、执行。

### P1/P2：性能基础设施

8. **命令搜索索引**：注册时预计算小写字段和展示文本，建立 token/前缀索引；搜索只对候选集评分，用稳定 top-k 替代全量插入排序，短 TTL 缓存上下文。验收：100、500、2000 条命令规模有冷/热 P50/P95，输入变化不重复路径解析和字符串拼接。

9. **窗口和上下文匹配索引**：按 exe/class/title 分层索引，保留精确匹配优先级；活动 HWND 捕获结果短 TTL 缓存，窗口切换和控件变化主动失效。验收：规则增长不会线性放大按键成本，并保持无类+无文件窗口不注册全局钩子。

10. **手势性能和质量基线**：拆分采样、预处理、方向链、模板匹配、候选选择耗时；建立真实用户独立测试集、负样本和混淆矩阵；记录 top-1、top-2、拒绝率、误触率、按应用/设备/DPI 分组 P95。验收：训练/测试分离，算法变更可比较准确率和延迟，低置信度显示候选和分数。

### P2：功能扩展

11. **手势训练闭环**：展示候选、来源层、分数和第二候选；支持纠错、追加样本、禁用/改名和可复现配置包。

12. **配置和插件可观测 UI**：显示 scope、当前来源、待应用状态、冲突插件和最近失败事件。

13. **真实桌面兼容层**：完成 Explorer、Total Commander、浏览器、终端、文件对话框、提权窗口和睡眠唤醒矩阵，再决定是否引入更复杂的输入注入策略。

## 建议的迭代节奏

| 迭代 | 目标 | 交付物 | 退出条件 |
|---|---|---|---|
| Iteration 0 | 可发布基线 | 整理后的提交组、修正后的 CI benchmark、输入安全矩阵、日志产物规则 | 所有现有探针通过；性能门禁能真实失败；未命中手势回放无回归 |
| Iteration 1 | 边界收口 | 配置服务迁移第一批、动作协议 v2 适配层、插件契约 v2、结构化错误报告 | 新代码不直接访问 g_Conf；插件冲突/依赖可诊断；旧命令行为保持一致 |
| Iteration 2 | 性能和识别质量 | 搜索/窗口索引、上下文缓存、独立手势数据集、混淆矩阵和稳定基准 | 目标规模达到延迟目标；算法变更有准确率和误触率证据 |
| Iteration 3 | 用户功能 | 训练闭环、配置可观测 UI、桌面兼容矩阵自动化 | 关键场景有真机记录和回归脚本；配置包可导入、纠错、回滚 |

## 暂不做的事项

- 暂不把所有模块一次性改成完全无全局状态；先用配置服务、命令注册表和插件上下文建立边界，再逐步迁移。
- 暂不承诺运行时动态卸载插件；当前生命周期按启动加载、退出清理设计，热重载需要独立资源所有权模型。
- 暂不根据现有 100% benchmark 宣称识别准确率达标；在独立真实数据和负样本完成前，只把它作为回归和性能测试。

这一路线先保护输入安全和可发布性，再收口配置、插件、执行边界，最后做索引和训练闭环。每一步都有独立验收证据，也不会把性能优化和行为重构混在同一个难以回滚的版本里。
